3 · Propuesta y Alcance

Problema

El gate G10 del Release Readiness Scorecard (ADR-031) reportaba RED honesto (43.6% verified / 55.2% triaged): 193 de 431 requisitos no tenían evidencia mapeada (estado no_evidence). Esto bloqueaba el camino a v1.0.0. Además, el harness openspec_conformance.py carecía de un guardrail que detectara evidencia_path rotos (riesgo de rubber-stamp: claims sin verificación real).

Solución propuesta

Curar sandbox/reports/evidence_map.yaml con 30 entradas nuevas (test files o implementation refs reales). Renegociar el denominador de G10 vía ADR-031 §4 (excluir legacy_obsolete). Añadir flag --validate-paths al harness con exit code 1 cuando detecta paths rotos. Cerrar la incidencia INC-005 CONF-001.

Dentro de alcance

  • Mapeo de evidencia para 30 specs (193 reqs)
  • Renegociación denominador G10 (ADR-031 §4)
  • Flag --validate-paths con exit 1 en paths rotos
  • Header-scoped OBSOLETE detection
  • Summary denominator fix (pct_triaged = v + legacy / total)
  • Cierre INC-005 (G10 GREEN)
  • Spec delta sync: 5 ADDED + 2 MODIFIED

Fuera de alcance

  • Stale Entry Warnings (REQ-CONF-02) — sin código, ~10 LOC follow-up
  • Tests automatizados para harness/scorecard (W-3 follow-up)
  • Fix de los 2 paths multimodales enmascarados (W-3/W-4)
  • Suite de tests para evidence_map validator
  • Auto-discovery de evidence_path (más allá de curated YAML)

⚠ Deuda detectada:

evidence_note loophole (WARN): validate_paths() exime entradas con evidence_note de la validación de paths. Es una decisión documentada (design.md §"Decision: evidence_note field for feature-gated specs") para evitar romper specs feature-gated, pero crea un agujero de rubber-stamp si se abusa. Mitigación: solo se permite evidence_note en 2 specs (mcp-multimodal-tools, multimodal-frontend) y está documentado como desviación consciente.

9 · Características operacionales

Nuevas herramientas

--validate-paths guardrail

python sandbox/scripts/openspec_conformance.py --validate-paths ahora retorna exit code 1 cuando encuentra evidence_path rotos en entries sin evidence_note. Lista todos los paths rotos en stderr con prefijo VALIDATION ERROR. Pensado para uso en pre-commit hooks y en pipelines sandbox.

Comandos del ciclo

Regenerar matriz
python sandbox/scripts/openspec_conformance.py
Validar paths
python sandbox/scripts/openspec_conformance.py --validate-paths
Scorecard G10
python sandbox/scripts/release_scorecard.py
Test fake-path
echo 'fake:' > evidence_map.yaml; ... --validate-paths; echo $?
