# Addendum to e90 — 2026-09-26 (correction: tools DO exist in `main`)

## What happened

The previous addendum (`addendum-2026-09-25.md`) stated:

> The revalidation cross-checked the tool inventory of `cognicode-mcp`
> v0.98.1 (built from HEAD, 2026-09-25) against the tool names reported
> in e90:
>
> - `graph_insights` — **NOT in v0.98.1 tools/list** (20 tools total).
> - `graph_communities` — **NOT in v0.98.1 tools/list**.

**This claim is obsolete for the current `main` HEAD.** A direct
grep against `origin/main` (post-C8, commit `2991e5e2`) shows that
both tools are registered, implemented, and exposed via MCP:

```bash
$ grep -rn "graph_insights\|graph_communities" crates/ docs/ | wc -l
44

$ grep -n "TOOL_GRAPH_COMMUNITIES\|TOOL_GRAPH_INSIGHTS" \
    crates/cognicode-explorer/src/mcp/explorer.rs
129:pub const TOOL_GRAPH_COMMUNITIES: &str = "graph_communities";
# (graph_insights is registered via graph_handlers.rs:519)
```

The code lives in:

- `crates/cognicode-core/src/application/services/graph_insights.rs`
  (360 lines — `GraphInsightsService::analyze`)
- `crates/cognicode-core/src/infrastructure/graph/analytics/community_detector.rs`
  (504 lines — `CommunityDetector::detect` + `surprising_connections`)
- `crates/cognicode-core/src/interface/mcp/handlers/graph_handlers.rs:290,519`
  (handler + tool registration)
- `crates/cognicode-graph-algos/src/algorithms/communities.rs`
  (Label Propagation implementation)

The handlers are tested in
`crates/cognicode-explorer/tests/graph_analyze_integration.rs`
(25 tests, all green).

## Implication for the G5 scorecard

The original e90 scorecard run measured `graph_insights`/`graph_communities`
with p95=367072ms / 53094ms. The addendum 2026-09-25 said "the
symptom does NOT apply to v0.98.1". **That conclusion was wrong.**
The symptom *does* apply to the current `main` HEAD — same code
paths, same hot loops. The only difference is the release line:
v0.98.1 is signed as production-ready contractual (C7) and the
scorecard was measured against v1.0.0-rc, but the underlying
algorithms are identical.

## Decision

- **The original v0.98.1 production-ready sign-off (C7) remains valid.**
  The C7 commitment is about the v0.98.1 binary and its documented
  tool surface. The `graph_insights`/`graph_communities` tools have
  always been part of that surface — the addendum's "not in v0.98.1"
  claim was an investigative error that does not undermine C7.
- **e91 carries forward unchanged in scope** — the algorithmic
  optimization plan still targets the same hot paths. Only the
  framing of "the problem belongs to v1.0.0-rc only" is corrected:
  the problem also applies to `main` HEAD, just less critically
  (because v0.98.x is feature-frozen by the Post-PRF SemVer policy
  in `docs/roadmap/MAINTENANCE.md`).
- **e91.W1 was reinterpreted** (see addendum 2026-09-26 in
  `openspec/changes/2026-09-25-e91-graph-insights-performance/proposal.md`)
  and is now CLOSED with commit `6f40a08b`: the algorithm metadata
  exposed via MCP is now honest (real `iterations` and `converged`,
  not hardcoded approximations). The remaining W2-W5 work
  (algorithmic optimization + budget spec) requires a real
  Tier-2/3 multi-repo fixture that does not exist in `main`.
