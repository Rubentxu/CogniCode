3 · Propuesta y Alcance

Problema

Los gates G10/G11/G12 del Release Readiness Scorecard (ADR-031) estaban incompletos o mentían: G10 no tenía harness, G11 daba falso negativo en detección de ADRs, G12 reportaba GREEN ignorando que CHANGELOG.md no existía y había ~85 ramas stale. La auditoría de exploración confirmó 430 requirements, 0% trazabilidad máquina, ~44 reqs legacy PG/SQLite post-E29, y 3 bugs en el scorecard.

Solución propuesta

Script ligero Python (openspec_conformance.py, ~133 LOC) que parsea spec.md con regex normalizado ^#{2,3}\s+Requirement, extrae 430 reqs, mapea a tests vía evidence_map.yaml, y emite conformance_matrix.{yaml,md}. Wireado al scorecard existente (gate_g10()) con umbral renegociado (≥90% verified + 100% triaged). Fixes puntuales en G11 (paths ADR + ACEPTADO) y G12 (tag + CHANGELOG + branch count). Script bash auxiliar prune_stale_branches.sh con dry-run obligatorio.

Dentro de alcance

  • Harness openspec_conformance.py
  • Wire G10 al scorecard (umbral renegociado)
  • Fix G11 (paths ADR-031/032 + check ACEPTADO)
  • Fix G12 (tag real + CHANGELOG + branch count)
  • CHANGELOG.md canónico (Keep a Changelog, v0.87.0+)
  • Branch pruning (dry-run + PR guard)
  • ADR-031/032 → ACEPTADO
  • 6/6 specs Tier-C marcadas OBSOLETE

Fuera de alcance

  • Tests automatizados para harness/scorecard (W-3 follow-up)
  • Escribir evidencia para 193 reqs no_evidence (CONF-001)
  • cargo test o campaña sandbox
  • Mover/archivar specs OBSOLETE de openspec/specs/
  • G3/G4/G5/G8 (fuera de alcance Fase 4)
