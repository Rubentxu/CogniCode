## Motivo de la excepción

B5 cierra 4 WUs (W1..W4) que satisfacen "safe refactoring &
authorized changes". Un usuario o agente puede preparar un cambio,
inspeccionar sus consecuencias y aplicarlo con autorización
explícita, sin perder capacidad de recuperación ante errores. La
release v0.101.15 incluye:

- B5.W1: `RefactorPlan` con id (uuid) + workspace_identity +
  AnalysisBasis (B2.W1) + edits + preconditions + risks + digest
  sha256 determinista. Edits/risks ordenados estructuralmente;
  paths no absolutos rechazados.
- B5.W2: `RefactorPreview` pura — mismo plan + mismos bytes =>
  byte-equal output. NUNCA muta. `verify_preview_no_mutation`
  sanity-check de mtimes.
- B5.W3: `apply()` con `AuthorizationToken` por canal separado
  (AAT-B5-03: read-only MCP NO adquiere write authority). Path
  validation (symlink/traversal escape rechazados, AAT-B5-02).
  Workspace state digest recomputado (rechaza si difiere).
  Transaccional: write to `.cognicode-staging/<plan_id>/`, fsync,
  atomic rename, rollback si falla.
- B5.W4: `RevalidationVerdict` con default `VerdictRefused` (B4.W5
  spine) — la revalidación es evidencia, no veredicto
  (AAT-B5-04). Reusa tipos B4 (ImpactResult, ArchitectureDiagnostic,
  FindingsReport). NO ejecuta comandos arbitrarios del repo.
