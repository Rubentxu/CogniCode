  grandes (`commands.rs`, `rmcp_adapter.rs`) viven bajo el soft cap

  se supera el soft cap y falla el build si se supera el hard cap.

  reutilizan `AnalysisBasis` (B2.W1) y `Severity` (B4.W2) en lugar
  de re-Declarar tipos propios.
- `b2_w1_analysis_basis_is_the_only_basis` — un solo `pub struct
  AnalysisBasis` definido en el árbol `cognicode-core/src/`.

  paralelo.

## Riesgos aceptados

Mismos riesgos que B1..B5 release (veredicto previo):

- `merge-gate:success` se emite manualmente vía `gh api` por SHA.
  El estado puede sobrescribirse por cualquier re-run posterior del
  gate automático. Patrón documentado en
  `docs/roadmap/production-ready/runbooks/MERGE-GATE-BYPASS-POLICY.md`
  §4.
- `bash scripts/test-full.sh` puede mostrar `rc=1` por OOM en el
  release build (`cargo build --release --workspace` killed por
  SIGKILL, rc=137). El test suite lib + tests (cargo test
  --workspace --lib --tests) exit 0. Los tarballs de release se
  construyen y verifican independientemente.
